## Findings and Decisions

### 当前进度盘点

### 已完成并可复用的工程底座

- **官方目录与图片采集。** 已有 131 英雄、960 皮肤的 SQLite 主库和 800 个本地图片文件；`source_key` 可避免重复 `skin_id` 覆盖。它是后续队列、证据、特征与报告的统一主键。限制是仍有 160 条记录没有对应的本地图片文件，且元数据完整度不足。
- **社媒数据链路。** 微博帖子/评论存储、MID/账号/关键词入口、清洗和显式反爬失败已存在；本地库有 50 帖和 4,409 条真实评论。它可为皮肤级舆情证据提供原料，但采集成功不等于已完成皮肤归因或情感维度标注。
- **VLM 与 33 维契约。** L1/L2/L3 管线、缓存/降级、33 维 `SkinFeatureVector`、来源和可用性标记、范围验证、导出与 QA 报告代码均已存在。当前特征库只有 2 条未验证记录，没有全量或核心队列批处理结果。
- **规则评估与业务分析。** `RuleEngine`、单皮肤 CLI、市场信号仓储、销售建议和分数—销售偏差分析已实现，可输出证据覆盖、置信度和缺失项。现行规则输出 7 个证据方面，并不是 PPT 中已验证的五维情感模型。
- **展示层。** Streamlit 已重构为组合概览、皮肤探索、皮肤详情和数据工作台四页；缺数据时 fail-closed。它可以承接采样、证据录入、覆盖率、雷达图和报告展示；当前无情感排名是门槛生效的预期行为。
- **现金价值与流程模拟。** 已有 49 条皮肤现金价值记录、365 天收入基线和 2 个共 179,520 行的可复现合成发票批次；合成微博评论单独存储。它们可用于审计、界面演示和"分数—销量"诊断，但不得进入情感评分或被称为市场事实。

### 待处理闭环

1. **标签融合尚未实现。** 专家式、社区、市场和人工偏好来源尚未按来源、覆盖率、冲突与置信度融合；不能将任一来源直接写成"真实情感溢价"。
2. **模型评估尚未具备前提。** 没有冻结的真实标签队列、独立真人偏好数据或足够的训练标签，因此 XGBoost/Ensemble 只能作为条件性基线，不能在本月被当作已验证预测器。
3. **Agent/MCP 环境尚未就绪。** 仓库内尚无 LangGraph 运行时、多智能体任务图或 MCP 服务实现；需搭建基础环境以支撑后续自动化闭环。

### 后续计划

#### 标签融合

- 实现来源感知融合，保留每个来源的分值、权重、证据数、时间、冲突和置信区间。
- 将现有 7 方面证据显式映射至五维（审美、归属、炫耀、收藏、惊喜），支持 abstain。
- 完成专家式、社区、市场和人工偏好来源的融合规则与单元测试。

#### Agent/MCP 环境搭建

- 搭建 LangGraph 运行时基础框架。
- 实现 MCP 服务骨架与核心工具 contract（`collect_evidence`、`extract_features`、`fuse_labels`、`build_report`）。
- 定义 Pydantic schema 和结构化错误，为后续多智能体协作提供稳定接口。
